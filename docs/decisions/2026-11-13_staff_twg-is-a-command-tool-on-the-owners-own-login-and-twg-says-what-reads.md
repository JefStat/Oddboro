- [staff] **Decision (2026-11-13): `twg`, the Teamwork Graph CLI for Jira, Confluence and Bitbucket, is a command tool like `gh` (2026-11-13). The office runs it as the owner's own twg login. The Odd gets `twg_read` and `twg_write`, and twg itself says which commands only read.** `twg` keeps its login in the owner's home and OS vault, so the office runs it with the owner's home and nothing else of its own environment (`outsideToolEnv`), and the Odd never sees the login. The owner signs in with `twg login` on their own computer. A connector of kind `command` with `cli: 'twg'` (`TWG_ID` in `packages/ledger/src/registry.ts`) needs no desk sign-in step. `twg_read` runs a command only when `twg help <command>` marks it `read` (`accessOf` in `twg-args.ts`, asked once per command path), and refuses any command twg marks `mutation` or `unknown`. `twg_write` runs every other allowed command, and at Draft each call waits on the desk with its exact arguments. The office allows only `jira`, `confluence`, `bitbucket` (and `bb`), `rovo`, `goals`, `projects`, `teams` and `context`. It refuses `admin`, `auth`, `login`, `setup`, `artifacts` and the other products, any flag that picks another login (`-p`, `-u`), any flag that reads or writes a file of this computer (`--output-path`, `--file-local`, `--files-from`), and any `@file` value. It adds `--output json` unless the Odd chose a format, and runs in a new empty folder. Output sits inside `<untrusted>` tags. A twg that is missing or signed out fails with a line that says so. Code in `apps/office/src/lib/server/twg-tool.ts` and `twg-args.ts`.
