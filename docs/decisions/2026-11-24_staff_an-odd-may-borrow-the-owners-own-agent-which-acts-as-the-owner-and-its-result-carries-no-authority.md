- [staff] **Decision (2026-11-24): an Odd may borrow the owner's own agent, a native Claude Code or Codex session behind Advanced mode. That agent acts as the owner, inside the native tool's own permissions, and the office adds no wall of its own. Its result reaches the Odd as the owner's own agent's work, with no `<untrusted>` tags, and gives the Odd no authority.** Oddboro holds two trust domains. Odds act inside the office's walls: levels, grants, the gateway, sandboxes and hard rule 4. The owner's native agent acts with the owner's logins and settings. Trust crosses between them only through acts of the owner, each of which can be taken back: turning on Advanced mode, which the ledger records (2026-11-11), and sharing one session with one Odd, in Projects or by a yes to that Odd's ask for it (2026-11-08). Going in, an Odd's instruction becomes the owner's act only when the owner sends it with Take over and send, or when that session lets that one Odd at Act send without asking. Coming out, `finishProject` in `packages/ledger/src/project-sessions.ts` puts the answer in the Odd's report and its thread's next run as it came. The answer never raises the Odd's level, grants, tools, folders or standing yeses, so what the Odd does next still waits where its own access says. The native agent may have read hostile text, such as a web page or an issue, so its answer can carry words meant to steer the Odd. The worst it can do is mislead the Odd inside the office's walls, never act past them. See `docs/project-sessions.md`, "How trust works".
